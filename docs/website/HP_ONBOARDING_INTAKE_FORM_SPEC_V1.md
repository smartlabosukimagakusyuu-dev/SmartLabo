## 0. 本書が前提とする正式決定事項

代表判断として確定済み。本書では再検討しない。

### 0.1 HP生成方式（方式C）

共通コンポーネント ＋ 業種別テンプレート ＋ 店舗データ ＋ 店舗写真 から
静的HPを生成する。店舗ごとに制作コードを複製せず、共通の生成元で一元管理する。

| 区分 | テンプレート | 対象業種 |
|---|---|---|
| A | **Beauty** | 美容室・ネイル・アイラッシュ |
| B | **Wellness** | 整体・エステ・パーソナルジム |
| C | **Private** | 個人サロン・小規模店舗 |

### 0.2 配信方針

- 最初の1〜5店舗は、1店舗ごとに独立した静的サイトとして公開する
- Phase 1 では GitHub Pages も利用可能とする
- **5店舗目までに**、GitHub Pages を継続するか別の静的ホスティングへ移すかを再評価する
- **公開・DNS変更・料金表示・法的表示は人が承認する。公開を完全自動化しない**

### 0.3 基本SEO（標準制作範囲に含む）

title / meta description / canonical / OGP / 構造化データ / robots / sitemap / 画像alt

- **検索順位・アクセス数・集客効果は保証しない**

### 0.4 料金表示

- 一般顧客向け店舗HPでは**税込総額を主表示**する
- 税別価格を掲載する場合も、必ず税込総額を併記する
- **税込・税別が不明な料金は公開しない**

> ★用語の混同に注意すること。
> 「税込総額を主表示」は **店舗 → 一般顧客** の料金（店舗HPに載るメニュー料金）の話である。
> 「50,000円〜（税別）」は **Smart Labo → 店舗** の制作料金であり、価格SSOT §1 のとおり
> 必ず「（税別）」を付けて表示する。両者は対象が異なり、矛盾しない。

### 0.5 確認用URL

- **標準制作工程に含む**（価格SSOT §2。修正2回の確認に使用する）
- 正式公開URLとは別にする
- 推測困難なURLを使用する
- `noindex` を設定する
- robots でクロール対象外にする
- 確認期限を設ける／最終承認後に削除または停止する
- **秘密情報・非公開の個人情報は掲載しない**
- **検索非掲載（noindex・robots除外）はアクセス制限や認証を意味しない**
- **店舗の最終承認前に正式ドメインへ公開しない**

### 0.6 プライバシー

- **標準50,000円〜の制作範囲に含む**（価格SSOT §2）
- 全店舗HPに基本的なプライバシーポリシーを用意する
- 基本テンプレートを使用する
- 店舗ごとに取得情報・利用目的・問い合わせ窓口等を確認する
- Smart Labo が**人の目で最終確認する**
- **完全な個別法務文書の作成、および専門家によるレビューは標準範囲外**
- **法的完全性を保証する表現は禁止**
- **法的内容をAI判断だけで公開しない**

### 0.7 標準問い合わせフォーム

- **標準50,000円〜の制作範囲に含む**（価格SSOT §2）
- 標準項目は5つ（名前／メールまたは電話／問い合わせ種別／問い合わせ内容／
  プライバシーポリシー同意）。詳細は §10.1
- 追加項目・大量の分岐・ファイル添付・予約確定・決済・外部システム連携は**追加見積り**
- **本工程ではフォームを実装しない**（§21）

### 0.8 Phase 1 の進め方

- フォーム**仕様**は本書で確定する
- **画像アップロード付きフォームはまだ実装しない**
- 画像は**店舗ごとの Smart Labo 指定クラウド共有フォルダ**で受領する（§12.7）
- 確認環境は **Smart Labo 管理下の環境**を使用する（§18.1）
- 実運用で不足項目・確認回数・制作時間を記録する（§20）
- フォームのシステム化は **Phase 2 で判断**する

### 0.9 支払い・請求（R2 確定）

- HP基本制作費は **50,000円〜（税別）**。標準50,000円の場合、**請求額は税込 55,000円**
- **着手金と残金には分割しない**（「着手金50%・残金50%」方式は採用しない）
- 契約成立後、**制作開始前に Stripe の請求書で一括請求する**
- **入金確認後に制作を開始する**（§3.4・§16.1・§19 DAY0）
- **Stripe の決済画面で顧客自身がカード情報を入力する。
  Smart Labo はカード番号・有効期限・セキュリティコード等を受領・保存しない**
- 制作開始後の追加作業は **記録 → 見積り提示 → 顧客承認 → 請求 → 入金確認** の順を必須とする
- **承認前に追加作業を開始しない。口頭だけの依頼を追加費用として請求しない**
- **追加請求が未払いのときは、追加部分を含む本番公開を行わない**（§18.3）
- HP制作費（一回限り）／HP保守（別サブスクリプション）／Salon利用料（別商品・別サブスクリプション）を
  **同一の請求へまとめない**
- **お金の処理は Stripe、契約・制作管理は案件管理**。「すべてStripeで完結する」とは言わない（§3.4）
- 詳細は §3.4、上位規定は価格SSOT §12

## 2. 本書の位置づけと運用ルール

1. 本書は Phase 1（最初の1〜5店舗）の**入力仕様のSSOT**である
2. フォームを紙・PDF・スプレッドシート・チャットのいずれで運用しても、**入力項目と必須区分は本書に従う**
3. 本書の項目を増減する場合は、**本書のVERSIONを上げる**。個別案件で勝手に増減しない
4. 価格・提供範囲に関わる変更が必要になった場合は、**先に価格SSOTを改定する**
5. Phase 1 の運用記録（§21）をもとに、Phase 2 の着手前に本書を v2 へ改定する

- Salon の同時提案は自然に行ってよいが、**押し付けない**（価格SSOT §7-3）
- 「HP制作が Salon 月額に含まれる」とは**言わない・書かない**（価格SSOT §7-4）

### 3.4 請求・決済ルール（R2 確定）

> ★上位規定は**価格SSOT §12**。本節はそれを工程へ落としたものであり、
> 価格・請求方法を独自に定義しない。齟齬がある場合は価格SSOT が優先する。

#### 3.4-1. HP基本制作費

| # | 規定 |
|---|---|
| 1 | 標準価格は **50,000円〜（税別）**。標準50,000円の場合、**請求額は税込 55,000円**（消費税10%） |
| 2 | **着手金と残金には分割しない。**「着手金50%・残金50%」方式は採用しない |
| 3 | 契約成立後、**制作開始前に Stripe の請求書で一括請求する** |
| 4 | **入金確認後に制作を開始する**（C-14 の記録が必須） |
| 5 | **Stripe の決済画面で顧客自身がカード情報を入力する** |
| 6 | **Smart Labo はカード番号・有効期限・セキュリティコード等を受領・保存しない。** フォーム・メール・チャット・電話のいずれでも受け取らない（§10.2 と同じ原則） |

#### 3.4-2. 契約時点で追加内容が確定している場合

基本制作費と追加費用を**同じ見積書・契約内容へ記載**し、
**合計額を Stripe の請求書で制作開始前に一括請求する。**

```text
（計算の書き方の例。固定価格ではない）
HP基本制作費       50,000円
追加ページ等       20,000円
小計               70,000円
消費税（10%）       7,000円
請求額             77,000円（税込）
```

> ★**この例を固定価格や標準追加料金として扱わない。**
> 「追加ページは20,000円」という標準料金は存在しない。
> **追加料金は案件ごとの見積りとする**（価格SSOT §4・§6）。

#### 3.4-3. 制作開始後に追加作業が発生した場合（順序を入れ替えない）

| 順 | 手順 | 記録先 |
|---|---|---|
| 1 | 追加希望を記録する | 案件管理 |
| 2 | **追加範囲・金額・納期への影響**を提示する | 案件管理 |
| 3 | **顧客から書面または記録可能な方法で承認を取得する** | 案件管理（承認者・承認日・承認方法） |
| 4 | Stripe で追加分の請求書を発行する | C-16＝請求済 |
| 5 | **所定の入金確認後**に追加作業または公開へ進む | C-16＝入金済 |

**必ず守ること**

- **承認前に追加作業を開始しない。**
- **口頭だけの依頼を追加費用として請求しない。**
- 外注費・有料素材・有料サービス等の**実費が発生する作業は、原則として入金確認後に発注・着手する。**
- 追加請求が未払いの場合、**標準範囲の確認までは進めてよいが、
  追加部分を含む本番公開は行わない**（§18.3）。

#### 3.4-4. 月額料金（制作費と混在させない）

| 商品 | 請求方法 |
|---|---|
| HP制作費・追加制作費 | Stripe の**一回限りの請求書** |
| HP保守・管理費（月額5,000円〜・税別） | 公開後に、**別の Stripe サブスクリプション** |
| Smart Labo Salon 利用料 | **HPとは別商品・別の Stripe サブスクリプション** |

- 3つを**同一の請求へまとめない**。
- **HP単独契約が可能であること、Salon契約を強制しないことは維持する**（§3.2・価格SSOT §7）。

#### 3.4-5. Stripe と案件管理の責任境界

| Stripe が持つもの | 案件管理が持つもの |
|---|---|
| 請求書 / 決済 / 入金状態 / 未払い / 返金・取消 / 領収記録 / 月額課金 | 見積り / 契約内容 / 追加作業の承認 / 制作進捗 / 店舗確認 / 公開承認 / Stripe 参照ID |

> ★**「すべてStripeで完結する」とは記載しない。**
> **お金の処理は Stripe、契約・制作管理は案件管理**という境界を守る。
> 案件管理が保持してよいのは **参照ID（customer ID / invoice ID 等）** までであり、
> カード情報・決済手段の実体を持たない（C-15）。

#### 3.4-6. 本工程で確定・実装していないこと

**実装済み・利用可能とは書かない。営業でもそう説明しない。**

Stripe API 連携／webhook／自動請求書発行／自動入金反映／Stripe Tax／
銀行振込対応／返金・キャンセル料の詳細規約／適格請求書発行事業者番号／
カード手数料の顧客転嫁／Payment Links の採否／AI Sales との自動連携

Phase 1 では、**請求書の発行・入金確認・記録はすべて人が Stripe 管理画面で行う。**

## 4. 入力項目の分類ルール

各項目には必ず次のいずれかを付与する。

| 必須区分 | 意味 |
|---|---|
| **必須** | 入力が無ければ DAY1 を通過させない |
| **任意** | 無くても制作を進行できる |
| **条件付き必須** | 指定条件を満たすとき必須になる（条件を必ず明記する） |

   A契約でも **M-06 税区分は店舗に必ず確認する**。ここは自動取得できない。

### 6.3 掲載できない料金表現

以下は入力させない。入力された場合は掲載せず、店舗へ差し戻す。

- 根拠のない割引率（例：「通常価格の50%OFF」で通常価格の販売実績が無い）
- 根拠のない「通常価格」「定価」「他店より安い」「地域最安」
- 効能・結果を保証する表現（例：「必ず痩せる」「完全に治る」「100%改善」）
- 期間の無い「今だけ」「期間限定」（M-16・M-17 が無いもの）
- 最上級表現（「No.1」「日本一」）で客観的根拠が示せないもの

- 効能の断定：「治る」「治療」「必ず改善する」「完治」「根治」「効果を保証」
- 医療行為と誤認させる表現：「診断」「処置」「医学的に」「〜症を治す」
  （医師・医療機関でない場合）
- 医薬品的な効能効果の標榜（薬機法）
- 客観的根拠のない最上級・比較優良（景表法）

**言い換えの方向（テンプレートの入力ヒントに埋め込む）**

| 使わない | 言い換えの例 |
|---|---|
| 肩こりが治ります | 肩まわりの張りが気になる方へ |
| 姿勢を矯正します | 姿勢の癖に合わせて整えます |
| 痩せます | 続けやすい運動と食事のご提案をします |

#### 8.2.2 ビフォーアフター画像（R1 確定）

**標準テンプレートでは使用しない。原則として受領・掲載しない。**

例外的に掲載する場合、**最低限すべて**を満たすことを必要とする。

| # | 必要条件 | 記録先 |
|---|---|---|
| 1 | 法令確認（薬機法・景表法・医療広告規制） | 案件記録 |

4. 対応内容を案件記録に1行で残す（値そのものは書かない）

## 14. プライバシー仕様

### 14.1 原則（R1 確定・標準範囲に含む）

- **標準50,000円〜の制作範囲に含む**（価格SSOT §2）。

- **問い合わせフォームを設置する場合は必須**（W-10 に「フォーム」を含む場合）。

- 店舗ごとに**取得情報・利用目的・問い合わせ窓口等を確認する**。

- 完全な個別法務文書の作成
- 専門家（弁護士・行政書士等）による法務レビュー

**禁止事項**

- **法的完全性を保証する表現を使わない。**
  「法的に問題ありません」「法令に完全に準拠しています」等は、
  提案・見積・納品物・口頭説明のいずれでも使わない。
- **法的内容をAI判断だけで公開しない**（§0.6）。

### 17.3 データ格納の原則（必ず守る）

1. **`contact.internal` 以下と、`legal.*` の同意・根拠・チェック記録は、

2. 文字列は**すべて HTML エスケープしたうえで出力する**。
   店舗入力をそのまま HTML として解釈しない。
3. URL は `https://` で始まることを検査したうえで出力する。
   `javascript:` `data:` `vbscript:` などを拒否する。
4. `menus[].priceExTax` のみが存在し `priceIncTax` が無いメニューは、**生成対象から除外する**（§6.1-2）。
5. `images[].rightsConfirmed = false` の画像は、**生成対象から除外する**。
6. `staff[].published = false` のスタッフは、**生成対象から除外する**。
7. **実在店舗の情報・個人情報を、仕様書・サンプルデータ・テスト用データに使用しない。**

## 18. 確認・公開

### 18.1 確認用URL（R1 確定・標準工程に含む）

**標準制作工程に含む**（価格SSOT §2）。修正2回（§18.2）の確認に使用する。

| 項目 | 規定 |
|---|---|
| 環境 | **Smart Labo 管理下の確認環境**を使用する（§18.1.1） |
| ドメイン | **正式公開ドメインとは別**にする |
| パス | **推測困難な文字列**を含める（案件番号や店舗名だけにしない） |
| `robots` メタ | **`noindex, nofollow`** を全ページに付与する |
| `robots.txt` | **クロール対象外**にする |
| 掲載内容 | **公開予定の情報だけを載せる。秘密情報・非公開の個人情報は載せない** |
| 正式公開 | **店舗の最終承認前に、正式ドメインへ公開しない** |
| 確認期限 | 発行から**5営業日**を目安に設定し、店舗へ明示する |
| 期限後 | **削除またはアクセス停止**する。放置しない |
| 記録 | `publication.previewUrl` と発行日・期限・停止日を案件記録へ残す |

> ★**検索非掲載（`noindex` ・robots除外）は、アクセス制限や認証を意味しない。**
> URLを知っている者は誰でも閲覧できる。したがって、
> 「見られては困る情報」を確認用URLへ置いてはならない。
> この点は、店舗へ確認依頼を送るときにも一文で伝える。

#### 18.1.1 Phase 1 の確認環境（R1 確定）

**Smart Labo 管理下の確認環境を使用する。**

GitHub Pages を使用する場合、次をすべて満たすこと。

| # | 条件 |
|---|---|
| 1 | 推測困難なパスを使う |
| 2 | 全ページに `noindex, nofollow` を付与する |
| 3 | robots でクロール対象外にする |
| 4 | **公開予定の情報だけを掲載する** |
| 5 | **秘密情報を載せない** |
| 6 | **非公開の個人情報を載せない**（§5.1 の `contact.internal`、§13.2 #5 と同じ検査を通す） |

> ★**GitHub Pages ＋ noindex は認証ではない。**
> 到達したブラウザには内容がそのまま表示される。
> 認証が必要な確認環境が要るなら、それは Phase 1 の標準構成の変更であり、
> 別工程で判断する。

### 18.2 修正

- **標準料金内の修正は2回まで**（価格SSOT §2）
- 複数の修正指示は**1回分としてまとめて**もらう
- 修正回数の残数（C-12）を、修正のたびに更新し店舗へ伝える

**軽微修正（標準範囲内）の例**

- 文章の文言修正・誤字修正
- 写真の差し替え（同じ用途・同じ枚数）
- 料金・営業時間・定休日の修正
- メニューの追加・削除（掲載情報量が5ページ相当を超えない範囲）
- スタッフの追加・削除
- 掲載順の入れ替え
- リンク先の変更

**追加見積りになる変更の例**（価格SSOT §4 と一致）

- 完全な作り直し
- テンプレート区分の変更（Beauty → Wellness 等）
- ページ追加（6ページ目相当以降）
- 完全オリジナルデザイン
- ロゴ制作・写真撮影
- 予約システム・EC・決済・会員機能
- 多言語対応
- 特殊アニメーション
- 特殊な外部サービス連携
- **修正3回目以降**
- 独自ドメインの取得・移管で特殊対応が必要な場合

### 18.3 公開条件（11項目・すべて満たすこと）

| # | 条件 | 確認者 |
|---|---|---|
