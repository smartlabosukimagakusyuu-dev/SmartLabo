## 15. 料金の二重管理対策

### 採用した方式

指示にあった「site-config.js に正規値を定義」案ではなく、**正規値を検証スクリプト側に持ち、HTMLは実テキストのまま、3か所を突き合わせる**方式を採用した。

```
docs/reviews/tools/check-prices.js   ← 正規値（CANONICAL）はここだけ
        ↕ 比較
website-v2/index.html                ← 実テキスト（data-price 属性は目印のみ）
website-v2/pricing.html              ← 実テキスト（data-price 属性は目印のみ）
```

```bash
node docs/reviews/tools/check-prices.js
```

終了コード 0 が一致、1 が不一致。

### この方式にした理由

1. **`site-config.js` を website-v2/ に置くと、ページから参照されないJSファイルが公開物に混ざる。** 表示に使わない前提なので、サイトに置く必然性がない。
2. **スクリプトを `docs/` に置けば、公開対象に絶対に含まれない。** GitHub Pages が配信するのは `WEBSITE/` だけで、`docs/` は対象外。`website-v2/tools/` に置くと本番切替時に「公開対象から外す」手順が増え、その手順を忘れる事故が新たに生まれる。
3. **HTMLの料金は実テキストのまま**なので、JS無効でも読め、検索エンジンにも見える（実測: 第26節）。表示をJavaScriptに依存させていない。
4. `data-price` 属性は「どこが料金か」を機械が特定するための目印にすぎず、**表示には一切使っていない。**
5. 外部ライブラリもビルド環境も追加していない（Node標準のみ、約150行）。

### 検証している内容

1. 料金の正規値と、2ページのHTML表記の一致
2. 人数別の計算例が、正規値からの計算と一致するか
3. 「税別」表記の有無
4. 未確定条件の語（最低契約期間・無料期間・返金・キャンペーン・割引 ほか8語）の混入
5. **ヘッダー・フッターが全8ページで同一か**（静的HTMLを8ファイルに分けているため、片方だけ直す事故が起きうる）
6. **パンくずの構造化データの有無と、画面表示の有無が一致しているか**（第32節・発見6の再発防止）
7. `Company OS`・取引先名などの禁止語が全ページで0件か

5〜7は料金の範囲を超えるが、同じ「複数ファイルの同期漏れ」という失敗を防ぐものなので同じスクリプトにまとめた。

### 料金を変更するときの手順

`website-v2/README.md` 第2-1節に記載した。**`check-prices.js` の `CANONICAL`・`index.html`・`pricing.html` の3か所すべてを更新する。1か所でも漏れるとスクリプトが失敗する。**

### 実際に検出した不整合

作成直後の初回実行で**18件**を検出した（詳細は第32節）。すべて修正し、最終実行は `[OK]`。

## 19. サービスをつくる理由

見出し「現場で使われなければ、業務は変わらない。」／5項目

1. AIツールを導入しても、何に使えばよいのかが決まっていなければ定着しません。
2. 顧客管理、記録、予定、タスクとAIが別々の場所にあると、使うたびに手間が増えます。
3. AIを単体で使うのではなく、日々の業務の流れの中へ組み込む必要があります。
4. その考えから、顧客・記録・タスク・予定とAIをひとつにした Smart Labo Works を開発しています。（強調）
5. そのうえで、利用者が内容を確認してから保存する設計を重視しています。（強調）

**「多数の企業へのヒアリング」「導入企業の声から開発」など、確認できない事実は書いていない。**

| Product / SoftwareApplication | **追加していない** | 指示どおり |
| BreadcrumbList（骨格ページ） | **出力していない** | `contact` / `privacy` / `terms` は画面にパンくずを表示していないため。構造化データは表示内容と一致させる（第32節・発見6） |
| FAQPage | **追加していない** | 代表判断2に従う。`pricing.html` にFAQがあるが追加していない |

### BreadcrumbList を追加した理由

1. 画面上にパンくずを表示しており、**表示内容と完全に一致する**構造化データを出せる（実測で一致を確認済み）。
2. 検索結果でのパンくず表示に使われ、サイト階層が正しく伝わる。
3. 2階層のみの単純な内容で、事実と異なる情報を混入させる余地がない。

出力内容（`features.html` の例）:

```
1. ホーム      https://smartlaboworks.com/
2. 機能        https://smartlaboworks.com/features.html
```

3ページとも、**画面のパンくず表示と構造化データの項目名・順序・URLが一致していること**をブラウザ実測で確認した。

1. `privacy.html` — `WEBSITE/privacy.html` の確定済み本文を移植。**法務文言は一字も書き換えない。**
2. `terms.html` — `WEBSITE/terms.html` の確定済み本文を移植。同上。
