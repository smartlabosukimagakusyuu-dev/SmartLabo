### PC / Mobile の出し分け方針

MASTER COMP は **PC 基準**として扱う。375px で単純縮小しない。

```html
<picture>
  <source media="(min-width: 861px)" srcset="...-pc.webp" width="1600" height="700">
  <img src="...-mobile.webp" width="800" height="1070" loading="lazy" decoding="async" alt="...">
</picture>
```

- `<picture>` + `media` で**1リクエストに収める**（display:none の二重読み込みを避ける）
- Phase 4D の導入メリットは PC 横長 / Mobile 3枚の構成で、`<picture>` では表現できないため
  例外的に display 切替を採用している。**新規セクションは `<picture>` を優先する**
- スマホは「PCページを縦にしただけ」にしない。Salon 広告 LP として成立させる

| Phase | 対象 | 必要素材 | 素材状態 | 着手可否 |

### ご提案の順序からの変更点

ご提示は Phase B を「サロンオーナーのお悩み」からとしていましたが、
**素材が未着のため着手しても placeholder のまま**になります。

そこで **B に「主要機能ナビの整理」（素材不要・CSSのみ）を差し込み**、
素材待ちの間に前進できるようにしました。お悩みは C へ後ろ倒しています。

**現実的な進め方**

```
今すぐ   : Phase B（機能ナビ）→ Phase H（料金以下の調整）  ※素材不要
並行     : C-1〜C-6 の発注、D-1〜D-3 の撮影
素材到着後: Phase C → D → E → F → G
最後     : Phase I（統合・OGP）
```

**クリティカルパスは素材**です。C（漫画・情景6点）と D（スクショ3点）の
着手が全体の完了時期を決めます。

## 5. 現行HTMLから残す技術資産

デザインは作り直すが、以下は**そのまま引き継ぐ**。

| 資産 | 内容 | 理由 |
|---|---|---|
| section id | `#features` `#benefits` `#screens` `#revisit` `#manga` `#pricing` `#website` `#flow` `#faq` `#cta` | 外部共有済みアンカーが壊れる |
| 問い合わせ導線 | `contact.html?type=consult&topic=salon#interests` ほか5種 | API 側は許可項目のみ再構成するため、URL 設計が実質的な契約 |
| SEO | title / meta description / canonical / OGP / `Service` / `FAQPage` 構造化データ | 既存の検索評価を落とさない |
| FAQ 機構 | `.faq` + `[data-faq]` + `main.js` のアコーディオン | JS なしでも全問読めるPE設計 |
| 実画面アセット | `salon-ui-*` / `salon-public-*` 6点 | 撮影仕様 SSOT に基づく正式素材 |
| CSS 基盤 | `.salon-theme` スコープ / `.sa-*` namespace / `salon-tokens.css` の `--sa-*` | 他ページへの影響を遮断する仕組み |
| コントラスト実測値 | DESIGN_PRINCIPLES.md の表 | 再計測の手間を省く |
| HERO 実装 | Phase 4B の HERO 一式（LCP設定含む） | 代表承認済み。作り直さない |
| 法務・掲載範囲 | check-legal.js が検査する条件 | 公開条件そのもの |

## 6. 捨てるデザイン構造

| 捨てるもの | 現在の該当 | 理由 |
|---|---|---|
| 黒枠4カードの漫画 | `.sa-koma`（`border: 3px solid var(--sa-ink)`） | 暖色の世界観から外れる。漫画を枠の意匠で表現している |
| Claude 自作の人物 SVG | `#manga` 4点 ＋ `#revisit` 1点（計5点） | 低品質。役割分担にも反する |
| 均一カードグリッド | `.sa-cycle__node`（4列）／`.sa-chain__item`（6列）／`.sa-more`（3列） | 情報数に合わせた自動カード化 |
| 白＋角丸＋影＋枠の反復 | 機械検出で **10ルール**該当 | カード感の主因 |
| ノード列としての攻める集客 | `.sa-cycle`（`repeat(4,1fr)`） | ストーリー図になっていない |
| 記号だけの HP 導線 | `.sa-chain`（アイコン＋ラベルのみ） | 人物・デバイスのビジュアルが皆無 |

> `.sa-*` の**命名と CSS 基盤は残す**。捨てるのは「カード化された見せ方」であり、
> namespace や `.salon-theme` スコープの仕組みではない。
