## 5. サービス全体フロー図の設計

指定された8工程を、**中央に背骨（縦線）を通し、人の工程を左・Smart Labo Worksの工程を右へ振り分けたタイムライン**として実装した。

```
        あなた                    │            Smart Labo Works
  ┌──────────────────┐          │
  │ AIに相談する      │──────────●
  └──────────────────┘          │          ┌──────────────────────┐
                                 ●──────────│ 対応方針を整理する    │
  ┌──────────────────┐          │          └──────────────────────┘
  │ 顧客対応・打ち合わせ│─────────●
  └──────────────────┘          │
  ┌──────────────────┐          │
  │ 活動内容を記録する │─────────●
  └──────────────────┘          │          ┌──────────────────────┐
                                 ●──────────│ 要点と次の行動を提案する│
                                 │          └──────────────────────┘
  ╔══════════════════════════════╪══════════════════════════════╗
  ║  あなた／内容を確認する（背骨を横断する関門・Smart Blueで強調） ║
  ╚══════════════════════════════╪══════════════════════════════╝
  ┌──────────────────┐          │
  │ 顧客・タスク・予定へ保存 │────●
  └──────────────────┘          │
  ┌───────────────────────────────────────────────────────────┐
  │ ↻ 次の相談は、ここまでの記録を踏まえたところから始まります。  │
  └───────────────────────────────────────────────────────────┘
```

**設計意図**

- **横一列にしていない。** 8工程を横に並べると1つあたりが狭くなり、PCでも読めなくなるため縦のタイムラインを採用した。横スクロールは使っていない。
- **「確認」を背骨を横断する関門として置いた。** 左右の交互配置の中で1か所だけ全幅になるため、視覚的に必ず目に入る。「AIが提案する」→「確認」→「保存する」の順序が図の形で固定され、**AIから直接自動保存されるようには見えない**。
- 「あなた」「Smart Labo Works」のラベルを各カードに付け、どちらが動く工程かを色だけに依存せず文字でも示している。
- 末尾にループの説明を置き、一度きりの直線ではなく日々繰り返す流れであることを示した。
- **スマホ（860px以下）では背骨が左端へ移り、自然な縦1列**になる。関門と締めの行はインデントして流れを保つ。

Section4（情報の流れ：左→中央ハブ→右）、Section5（6ステップの横並び）とは別の見せ方にしており、同じ図の繰り返しになっていない。

## 7. 画面取得方法

| 項目 | 内容 |
|---|---|
| 撮影対象 | Smart Labo Works ライト（汎用版） |
| 起動方式 | ビルド済み `dist/` を読み取り専用で配信し、APIサーバーを隔離起動 |
| AI | **無効**（`AI_ENABLED=false`）。外部AI APIへは一切接続していない |
| DB | 製品の `data/` から **scratchpad へコピーした使い捨てDB** を使用。元DBは読み取りのみ |
| 認証 | 製品の初期データに含まれるデモ用アカウント。値は本書に記載しない |
| 撮影 | Puppeteer（既存の devDependency）。1360×850、deviceScaleFactor 1 と 2 |
| 出力 | WebP（quality 80〜82） |

**製品リポジトリ（`smartlabo-works-lite`・`smartlabo-works`）には一切書き込んでいない。** 起動スクリプト・DBコピー・撮影スクリプトはすべて scratchpad 側に置き、リポジトリ内のファイルは変更していない。

撮影スクリプトには**撮影直前の自動チェック**を組み込み、次のいずれかを検出したらその画面を保存せずスキップするようにした。

- 「削減」「改善率」の文字列
- 「ミライエ」の文字列
- `example` を含まない実在ドメイン形式のメールアドレス
- APIキー・Bearerトークンらしき文字列

掲載した4画面はすべて **全項目 false**（検出なし）で通過している。

## 10. 選ばれる理由

見出し「AIを導入するだけで終わらせない。」／5項目。カードではなく**連番＋罫線のリスト**にして、Section8のカード列と見え方を変えている。

| # | 見出し | 要点 |
|---|---|---|
| 01 | 業務の中で使える | AIだけを別画面で使うのではなく、顧客・記録・予定・タスクとつながった状態で使える |
| 02 | 確認してから保存 | 自動反映しない。何が記録されるかを人が決められる |
| 03 | 初めてでも使いやすい | 画面の項目と操作を絞っている |
| 04 | 企業ごとに情報を分離 | 会社ごとにデータを分けて管理する設計 |
| 05 | 導入後も改善 | 使われ方や要望を伺いながら調整を続ける |

**「絶対安全」「完全」「誤りがない」「必ず成果が出る」といった断定表現は使っていない。** 04では「設計です」「表示されます」と事実の範囲で記述し、技術的なセキュリティ詳細には踏み込んでいない。

## 13. FAQ

指定の8問すべてを掲載した。

**実装方式**

- `<button>` によるアコーディオン。`aria-expanded` / `aria-controls` を設定し、回答側は `role="region"` + `aria-labelledby` で質問と結び付けている。
- **回答はHTMLに直接記述している。** JS内には持っていない。
- **JS無効時は全問が開いた状態で読める。** 初期HTMLでは `aria-expanded="true"`・パネルに `hidden` なしとし、JSが動いたときだけ先頭以外を閉じる（プログレッシブエンハンスメント）。JSが失敗しても質問と回答が消えることはない。
- 複数を同時に開ける仕様。
- 見出し構造は `h2`（よくある質問）→ `h3`（各質問）→ ボタン。
- キーボードで Enter / Space による開閉、`aria-expanded` の同期を実測で確認済み。
- ボタンの高さは 60px（タップ領域44px以上）。

**FAQ構造化データ（FAQPage）は追加していない。** 指示のとおり、勝手に追加しない方針に従った。追加する場合は、Googleの現在の表示方針を確認したうえで別途判断いただきたい。
