## 3. 採用したフォーム配置方式

**同一オリジンを既定とし、別オリジンでも動く実装**にした。

```
contact.html（フォーム）
   └─ action / data-endpoint = "/api/contact.php"   ← 既定は同一オリジン
          ↓
      contact-api/public/  を XServer の public_html/api/ へ配置
          ↓
      設定は public_html の「外」の private/contact-config.php
          ↓
      指定メールアドレスへ送信（保存はしない）
```

コードは `contact-api/` に置いた。**`website-v2/` の中にPHPを置いていない。**
GitHub Pages はPHPを実行せず `.php` をテキストとして配信するため、`website-v2/` に置くと
**ソースが丸ごと公開されてしまう**（受信先アドレスや検証ロジックが露出する）。

## 4. 同一オリジンにできるか

**現在の構成のままでは、できない。**

`smartlaboworks.com` は GitHub Pages を向いており、Pages は静的ホスティングのため PHP を実行できない。
同一オリジンを成立させるには、**apexドメインの向き先を XServer へ移す**（サイト本体をPagesから移設する）必要がある。
これは DNS・`CNAME`・`pages.yml` に関わる判断であり、いずれも変更禁止のため実施していない。

そのため、**どちらの構成でも動く実装**にした。

| 構成 | 内容 | 必要な作業 |
|---|---|---|
| **A. 同一オリジン**（代表方針・推奨） | `smartlaboworks.com/api/contact.php` | apexをXServerへ移設。`action` は現状のままでよい |
| **B. 別オリジン**（現構成を維持） | `form.smartlaboworks.com/contact.php` | `action` と `data-endpoint` を絶対URLへ変更。CORSは実装済み |

現在は **A を既定値**にしてある。Bを選ぶ場合の変更は `contact.html` の2箇所と設定の `allowed_origins` のみ。

**この選択は代表判断が必要です（第24節）。**

## 7. PHP処理内容

`contact-api/public/contact.php` の処理順序。

```
1. POST以外を拒否（OPTIONSはCORSプリフライトとして204）
2. 本文サイズの上限（既定20,000バイト）
3. Content-Type の確認（JSON または form）
4. 設定の充足確認（不足なら理由を明かさず500）
5. Origin / Referer が許可一覧に含まれるか
6. honeypot・時間差（自動送信の疑いは静かに拒否）
7. CSRFトークン
8. 送信間隔制限
9. 文字コード（UTF-8）の確認
10. 入力検証
11. メール送信（例外は捕捉して「送信できませんでした」に変換）
```

応答は2種類。`Accept: application/json` または `X-Requested-With: fetch` ならJSON、
それ以外（JavaScript無効の通常フォーム送信）は簡単なHTML。

### 送信方式（採用理由）

```
JavaScript あり → fetch で JSON を POST → JSON で応答
JavaScript なし → 通常の form POST      → HTML で応答
```

`<form method="post" action="/api/contact.php">` をそのまま使い、JavaScript は
「体験を良くするだけ」の上乗せにした。**JSが読み込めなくても入力内容が失われない。**
これを採ったのは、指示にあった「JavaScriptが無効でも入力内容が消えるだけの危険な挙動にしない」を
最も確実に満たせるためである。

## 8. セキュリティ対策

| 要件 | 実装 |
|---|---|
| POST以外を拒否 | ● 405（`Allow: POST`） |
| Content-Type確認 | ● JSON / form 以外は 415 |
| サーバー側必須チェック | ● 全項目 |
| メールアドレス形式 | ● `FILTER_VALIDATE_EMAIL` ＋ 改行検査 |
| 文字数上限 | ● サーバー側を正とする |
| 改行コードの正規化 | ● 1行項目は空白へ、複数行は `\n` へ |
| ヘッダーインジェクション対策 | ● ヘッダーへ入る値からCR/LF・制御文字を除去。Reply-Toは直前に再検証 |
| HTMLタグ除去 | ● `strip_tags` ＋ 実体参照の復元。本文はプレーンテキスト |
| CSRF対策 | ● HMAC署名＋有効期限（第9節） |
| 同一オリジン確認 | ● 許可一覧との完全一致 |
| Origin / Referer確認 | ● Originが無い場合はRefererを見る。どちらも無ければ拒否 |
| honeypot | ● 画面に出ない項目に入力があれば拒否 |
| 送信間隔制限 | ● 既定10分3件（第10節） |
| 同一IPからの連続送信制限 | ● 同上（**ハッシュ化したIP**で判定） |
| 巨大リクエスト拒否 | ● `Content-Length` と実本文の両方で 413 |
| エラーで内部情報を出さない | ● 応答は定型文のみ。理由コードは項目名だけ |
| PHPエラーを画面へ出さない | ● `display_errors=0`。例外は捕捉して定型文へ |
| 内容をログへ保存しない | ● 失敗時も固定文言のみ（`[contact] mail send failed`） |
| 受信先を応答に含めない | ● 一切含めない |
| IPを恒久保存しない | ● 生のIPは保存しない。HMACの先頭32文字のみ |

CORSヘッダーは**許可一覧に一致したOriginにだけ**返す（ワイルドカードは使わない）。

## 9. CSRF対策

トークンは `csrf-token.php` が発行する。形式は `発行時刻.ランダム.HMAC署名` で、**サーバー側に状態を持たない**（有効期限2時間）。
静的HTMLではページ生成時にトークンを埋め込めないため、JavaScriptが取得して隠し項目へ入れる。

### 設計判断（重要）

このエンドポイントには**ログインもセッションも無い**。偽装リクエストで起こりうるのは
「問い合わせメールが1通余分に届く」ことであり、利用者になりすまして操作されるものではない。
したがって、ここでのCSRF対策は**自動送信を増やしにくくするための多層防御の一つ**として扱った。

- JavaScript あり → トークンを必須とし、不一致は 403
- JavaScript なし → トークンが無いため、**Origin/Referer一致・honeypot・時間差・送信間隔制限をすべて満たしたときのみ**受け付ける

トークンを常に必須にしたい場合は、設定の `require_csrf_always` を `true` にする。
**その場合、JavaScript無効の環境からは送信できなくなる。** どちらを採るかは運用判断で切り替えられる。

## 10. honeypotとレート制限

**honeypot**: 画面外に置いた `website` 項目に入力があれば拒否（`aria-hidden` かつ `tabindex="-1"`。`display:none` にはせず、埋める挙動を検出できるようにしている）。
あわせて、フォーム表示から送信までが既定3秒未満なら拒否する。

**送信間隔制限**

| 項目 | 内容 |
|---|---|
| 保存場所 | `private/ratelimit/<ハッシュ化したIP>` |
| 保存内容 | **送信時刻（UNIX秒）の一覧のみ。問い合わせ内容は保存しない** |
| IPの扱い | **生のIPは保存しない。** `ip_hash_secret` を鍵にしたHMACの先頭32文字（復元不可） |
| 保存期間 | 既定10分。期間を過ぎた時刻は読み込み時に破棄 |
| 自動削除 | 1時間以上更新の無いファイルはリクエストのたびに削除 |
| 権限 | ディレクトリ 0700 / ファイル 0600。`private/` はWebから全拒否 |
| 上限 | 既定10分あたり3件 |

書き込めない環境では制限をかけずに通す（他の対策で守る）。

**外部CAPTCHAは導入していない。** 迷惑メールが実際に発生した場合、CSRF検証の直後へ
Turnstile等の検証を1ブロック追加できる構造にしてある。

## 11. メール設定方式

- **プレーンテキスト**
- `From` は**このサイトのドメインのアドレス**（設定の `from_email`）。利用者のアドレスは使わない
- 利用者のアドレスは `Reply-To`。入れる直前にCR/LFを除去し、形式を再検証する
- envelope-from を `-f` で自ドメインに固定（迷惑メール判定対策）
- 件名・表示名は RFC 2047 で符号化。**`mbstring` が無い環境でも動く自前の実装を用意**

**受信メールに含める内容**: 受付日時 / 問い合わせ種別 / 会社名 / お名前 / メールアドレス / 電話番号 / 利用予定人数 / お問い合わせ内容

**自動返信は実装していない。** 到達性・なりすまし・文面管理・二重送信の検討範囲が広がるため、
候補として報告するに留める（第24節）。

### .gitignore の影響範囲


## 19. 検証スクリプトの方針変更

WEB-V2-6で入れた「フォーム要素混入チェック」は正式実装により失敗するため、方針を変更した。

| 新方針 | 実装 |
|---|---|
| `contact.html` だけ正式フォームを許可 | `FORM_PAGES = ['contact.html']` |
| その他ページへのフォーム混入は禁止 | `<form>` `<input>` `<textarea>` `<select>` を検出 |
| 許可された送信先以外は禁止 | `action` / `data-endpoint` を `/api/contact.php` に限定 |
| 外部フォームサービス禁止 | Formspree / Googleフォームを検出 |
| mailto禁止 | `mailto:` を検出 |
| ダミー送信先禁止 | `action="#"` / `action=""` / `example.com/...` を検出 |
| GET送信禁止 | `method` が `post` 以外なら失敗 |
| 秘密情報らしい文字列の検査 | 鍵の名称・長い16進文字列・APIキー形式 |
| 受信メールアドレスの混入検査 | 公開HTML/CSS/JSに Gmail・自社ドメインのアドレスが無いこと |

**検知できることを確認済み**: 意図的に違反（外部送信先・他ページのフォーム・受信アドレスの記載）を入れたところ、
**6件すべてを検出**し、元に戻すと `[OK]` に戻った。

## 23. 本番配置手順案 / ロールバック手順案

### 配置手順（代表承認後）

1. XServerのサーバーパネルで対象ドメインの **PHP 8.0以上**を選択
2. `contact-api/public/` の中身を `public_html/api/` へアップロード
3. `contact-api/private/` の中身を**ドキュメントルートの1つ上**へアップロード
4. `contact-config.example.php` を `contact-config.php` としてコピーし、値を設定
   - `to_email` / `from_email` / `allowed_origins`
   - `csrf_secret` / `ip_hash_secret` は `php -r "echo bin2hex(random_bytes(32));"` で生成
5. パーミッション設定（`private/` 700、`contact-config.php` 600）
6. **`mode` を `test` のまま**フォームから送信し、成功表示を確認
7. `mode` を `live` に変更し、**関係者のアドレス宛で1件だけ**実送信を確認
8. 迷惑メールフォルダに入っていないかを確認（SPF/DKIM）

構成B（別オリジン）を採る場合は、加えて `contact.html` の `action` と `data-endpoint` を
`https://form.smartlaboworks.com/contact.php` へ変更する。

### ロールバック手順

| 状況 | 対応 |
|---|---|
| フォームに不具合がある | `contact.html` を1つ前のコミットへ戻す（準備中パネルの表示に戻る）。API側の削除は不要 |
| 迷惑メールが大量に届く | 設定の `rate_limit_max` を下げる、または `require_csrf_always` を `true` にする。恒久対策としてTurnstileを追加 |
| メールが届かない | `mode` を `test` に戻し、フォームは動くが送信しない状態にする。原因（SPF/DKIM/宛先）を切り分ける |
| APIを完全に止めたい | `public_html/api/` を削除またはリネーム。サイト本体には影響しない |

いずれも **`WEBSITE/` と `master` には触れない**。
