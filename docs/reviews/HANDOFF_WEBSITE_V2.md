## 2. これは何のプロジェクトか

株式会社スマートラボの公式サイトを、Version 1 から **Version 2 へ作り直す**仕事です。

- **現行の公開サイト（v1）** … `WEBSITE/` フォルダ。GitHub Pages で公開中。**触らない**
- **新サイト（v2）** … `website-v2/` フォルダ。ローカルのみ。**まだ公開していない**

v2 が完成し、代表の承認を得てから `WEBSITE/` を置き換えて公開します。

---

## 3. 絶対に触ってはいけないもの

毎回の指示で繰り返し明示されている禁止事項です。

| 対象 | 理由 |
|---|---|
| `master` ブランチ | 本番の公開元 |
| `WEBSITE/` | 現在公開中のサイト本体 |
| `.github/workflows/pages.yml` | これを触るとデプロイが走る |
| `WEBSITE/CNAME`（`smartlaboworks.com`） | 消えると独自ドメインが即座に切れる |
| `DESIGN_ASSETS/` | 正式ロゴのSSOT。読み取り専用 |
| `PROJECT_BIBLE/` `BRAND/` | 規範文書 |
| `xserver-form/` | v1の問い合わせ資産 |
| `smartlabo-works` / `smartlabo-works-lite` | 別製品のリポジトリ |

**push・masterへのマージ・本番公開はすべて禁止**です。毎工程、代表のレビュー待ちで停止します。

### なぜ本番に影響しないのか

`.github/workflows/pages.yml` のデプロイ条件は
`branches: [master]` **かつ** `paths: ["WEBSITE/**", ".github/workflows/pages.yml"]` の **AND** です。
作業は `website-v2` ブランチの `website-v2/` 配下なので、ブランチとパスの両方で条件を外しています。
さらに配信対象は `path: "WEBSITE"` のみです。

## 12. 本番切替とロールバック（承認後にのみ実行）

### 切替

1. `website-v2` ブランチで最終確認
2. **全ページから `dev-banner` の行を削除する**
3. `master` から `release/website-v2` を作成
4. `WEBSITE/` の中身を `website-v2/` で置き換える
   - ★**`WEBSITE/CNAME` を必ず残す**（消えると独自ドメインが切れる）
   - ★**`WEBSITE/app.html` を必ず残す**（デモ画面。全ページのCTAから参照）
   - `product.html` / `real-estate.html` の扱いは**要代表確認**
     （GitHub Pages は301を設定できないため、削除する場合はSEO影響の確認が必要）
5. 差分が `WEBSITE/` 以外に及んでいないことを確認してコミット・push
6. Actions の成功と、実ブラウザでの表示を確認

### ロールバック

- **切替前** … `git branch -D website-v2` で作業前に戻る（本番は元から無影響）
- **切替後** … `git revert <切替コミット>` → push。1〜2分で v1 に戻る
  （`reset --hard` + force push は使わない）
