# Smart Labo Salon — ページ構造

Salon ページ（`WEBSITE/salon.html`）の正式な構造思想。

---

## 大原則

> **各セクションを「カード一覧」に変換しない。
> 各セクションにそれぞれ異なる見せ方を与える。**

同じ見せ方が2つ続いたら、それは設計の失敗を疑うサイン。
読み手がスクロールしていて「さっきと同じ形だ」と感じた時点で、
営業資料ではなくテンプレートになっている。

---

## セクション構成と、それぞれの見せ方

**この順序は MASTER COMP（DESIGN SSOT）に一致させたものである（REBUILD-2 代表判断で確定）。**

| # | セクション | id | 見せ方 | 主役 |
|---|---|---|---|---|
| 01 | HERO | `#hero` | 写真＋浮遊UI | 正式人物ビジュアル |
| 02 | 主要機能 | `#features` | 横一列のアイコンバー（コンパクト） | アイコン＋機能名 |
| 03 | Salonでできること | `#screens` | 左に番号付き説明32%／右に実画面2×2で68% | 実画面 |
| 04 | 導入するとこんなに変わる | `#benefits` | **3シーン漫画**（横1枚・全幅の帯） | 漫画 |
| 05 | 待つ集客から攻める集客へ | `#revisit` | **ストーリー図**（循環フロー） | 図解＋人物 |
| 06 | サロンオーナーのお悩み | `#manga` | **4コマ漫画** | 漫画 |
| 07 | HP→予約→接客→再来店 | `#website` | PC/スマホ＋人物＋矢印 | 導線図 |
| 08 | 料金 | `#pricing` | **HTML中心**（画像に価格を焼かない） | 数字 |
| 09 | 導入フロー | `#flow` | HTML中心（ステップ） | 手順 |
| 10 | FAQ | `#faq` | HTML中心（アコーディオン） | 文章 |
| 11 | 最終CTA | `#cta` | **明るいSalonトーン**・中央寄せ | CTA |

### 旧順序へ戻さない

Phase 2 で承認していた「HERO → 機能 → **導入メリット** → できること」は
**REBUILD-2 の代表判断で破棄された**。
`#benefits` を `#screens` より前に置き直さないこと。
また、料金のあとに補足セクションを挟まない（料金 → フロー → FAQ → CTA で終える）。

### セクションid は変えない

上記の `id` は外部へ共有済みのアンカーになりうる。
順序を入れ替えても **id は維持する**。
ヘッダーナビの並びは、ページの出現順に合わせる。

## セクションごとの詳細

### 01 HERO

- 左：ブランド表示／H1／短い説明（1文）／3メリット／CTA2件／補助説明
- 右：正式な人物ビジュアル（写真またはハイクオリティイラスト）
- 「先着20店舗／創業メンバー募集中」は **HTML バッジ**で持つ（画像に焼かない）
- 画像内に同種の表示がある場合は、**どちらか一方に整理**して二重表示にしない
- LCP 要素。`fetchpriority="high"` ／ `loading` 属性なし ／ `preload` は**この1点のみ**
- 1440px で 1画面〜1.2画面、375px で 1.2〜1.5画面以内

### 02 主要機能

- **アイコン＋機能名だけ**。長文説明はここでは不要（詳細は後続セクション）
- PC は横一列、1080px で4列、520px で2列コンパクト
- HERO 直下に少し重ねて置き、**FV＋この帯だけで商品全体像が分かる**ことを狙う

### 03 導入するとこんなに変わる

- 白いカード3枚に**しない**
- 3シーンが1枚につながった横長イラストを**全幅の帯**として置く
- 帯の地色を画像の地色と一致させ、上下をセクション背景へなじませる
- 見出し・短い補足・導線リンクは HTML で保持
- 番号バッジを帯の下端にまたがせ、画像とテキストを縫い合わせる
- テキストの列幅を画像内シーンの実寸比に合わせる
- スマホは横長を縮小せず、シーン単位の個別素材で縦再構成

### 04 Salonでできること

最終形は「カード一覧」ではなく **漫画＋実画面＋HTMLリンクの大きなストーリー**。

流れ：

```
HP → 24時間WEB予約 → 予約管理 → 顧客カルテ → 接客メモ
   → AI整理 → 次回来店準備 → LINE → 再来店
```

- **機能名は HTML**。画像には人物・情景・補助UIのみ
- 実画面（`assets/images/salon/salon-ui-*.webp`）を大きく見せる
- 画面ごとに「この画面で何ができるか」を1〜2行で添える
- 実画面を置く節には必ず「※掲載画面はデモ用の架空データです。」を表示する
- 完成カンプを**そのまま縮小表示して文字を読ませる実装にはしない**

### 05 待つ集客から攻める集客へ

ページの見せ場。背景を他と変え、このセクションだけ見ても考え方が伝わる状態にする。

```
予約に空き → 対象候補を確認 → 人が対象を選ぶ → 人がLINE送信
          → 予約 → 来店 → 記録 → 次回へ（循環）
```

- **ステップ名は HTML で保持**
- 漫画人物・吹き出し・情景を背景／横に配置する
- 「人が決める」「人が送る」を視覚的に強調する
- **AI が自動送信するように誤認させない**（営業SSOTの禁止表現）

### 06 サロンオーナーのお悩み

- **4コマ漫画そのものを大きく見せる**。カードに小さく押し込まない
- 扱う悩み：広告費／予約管理／前回接客／最近来ていないお客様
- スマホでは**1コマずつ大きく**表示する
- 悩み → 解決への導線を1本の流れにする（漫画の後に解決セクションへ送る）

### 07 HP→予約→接客→再来店

- PC・スマホ・HP画面・予約画面を**ひとつのストーリービジュアル**として見せる
- HTML で保持する語：HP／24時間WEB予約／Salon予約管理／顧客情報／再来店
- 店舗ホームページ制作は **Salon とは別サービス**であることが視覚的に分かるようにする

### 08 料金

- **HTML 中心。価格を画像に焼き込まない**（更新性・検索性・A11y のため）
- 創業メンバープランを明確に主役にする（月額を大きく／「先着20店舗」を円バッジ）
- Standard は基準として読めるが控えめに
- ホームページ制作は**別色・別ブロック**で、別商品であることを見た目で示す
- 打ち消し線による二重価格表示・割引率表示はしない

### 09 導入フロー ／ 10 FAQ

- HTML 中心。FAQ は既存の `.faq` ＋ `main.js` のアコーディオンを流用する
- FAQ は JS が動かなくても全問読める状態を保つ（プログレッシブエンハンスメント）

### 11 最終CTA（明るいSalonトーン）

**REBUILD-2 代表判断：旧ルール「最終CTA＝暖色ダーク」は破棄した。**

- 地色は **淡いピンク／白／Salon Pink**。必要ならオレンジをアクセントに使う
- **暗色地・白抜き文字へ戻さない。** `--sa-bg-deep` `--sa-on-deep` `--sa-on-deep-2`
  `.btn--on-inverse` は削除済みで、復活させない
- カンプ下部の「まずは相談してみよう」という軽さを再現する
- **QRコード／LINE相談／メールアドレス直書きは置かない。**
  正式な問い合わせフォームへのCTAを主役にする
- 主CTA「まずは無料で相談してみる」／副CTA「資料を請求する」
- 主CTAの周囲に、相談できる内容を短いHTMLテキストで添えてよい
  （導入について／自分のサロンに合うか／料金や機能について）。
  **新しい未提供機能・実績・効果保証は書かない**
- 最終CTA から アウトロ帯・フッターへ、色の切れ目なくつなぐ

## セクション間のつながり

- 背景色をセクションごとに変え、単調な反復を避ける
  （白／アイボリー／ベージュ／薄ピンク／淡いピンクのグラデ）
- **暗色の面はページのどこにも作らない**（REBUILD-2 代表判断）
- ただし**派手にしすぎない**。Salon 専用パレットの範囲内に留める
- 直前のセクションと同じ地色・同じレイアウトを続けない
  （実装後に隣接セクションの `backgroundColor` を実測して重複がないか確認する）
