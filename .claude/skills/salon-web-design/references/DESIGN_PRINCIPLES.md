# Smart Labo Salon — デザイン原則

Salon ページの見た目に関する正式な判断基準。
迷ったときはこの文書の順に従う。

---

## 1. WORLD ／ 世界観

Smart Labo Salon の世界観は次のとおり。

```
暖かい / 親しみやすい / 女性向け / サロンらしい / 上品 /
漫画的 / 見て理解できる / 営業資料として強い
```

**Smart Blue（#2563EB）は会社ブランドとして残すが、Salon ページでは主役色にしない。**
会社トップ（`index.html`）や Smart Labo Works は Smart Blue のままにする。

### Salon 側のパレット

実装は `assets/css/salon-tokens.css` の `--sa-*` を使う。
`:root` ではなく `.salon-theme` スコープに定義してあるため、他ページへは影響しない。

### コントラストの実測値（勝手に色を作らない根拠）

| 前景 | 白 | アイボリー | ベージュ | 判定 |
|---|---|---|---|---|
| `--sa-pink` #C2415F | 4.98 | 4.74 | **4.24** | ベージュ地では AA 未達。`--sa-pink-deep` を使う |
| `--sa-pink-deep` #A8324E | 6.50 | 6.18 | 5.53 | ✅ |
| `--sa-pink-bright` #E0567A | 3.63 | — | — | **本文禁止**。大文字・装飾のみ |
| `--sa-orange` #A8511F | 5.44 | 5.17 | 4.63 | ✅ |
| `--sa-ink` #2E2A28 | 14.21 | 13.51 | 12.10 | ✅ |

**淡いベージュ地（#F6D9C4）にオレンジ文字は 4.05 で AA 未達。**
その組み合わせが必要なときは「白文字＋オレンジ塗り（5.44）」にする。

新しい色を足す前に、必ずコントラストを実測してから決める。

## 2. VISUAL FIRST ／ 画像は情報構造の一部

画像は飾りではない。**人物・漫画・情景がセクションの情報構造そのもの**である。

可能な限り、

```
画像  ＋  HTML文字  ＋  HTMLリンク
```

を一体化させる。画像の下にテキストブロックを別置きするのではなく、
番号バッジを画像の境界にまたがせる、吹き出しが画像の外へはみ出す、
テキストの列幅を画像内シーンの実寸比に合わせる、といった方法で縫い合わせる。

---

## 3. NO CARD DEFAULT ／ カードを既定にしない

**情報が3個あれば3カード、4個あれば4カード、という自動判断をしない。**

カードは、次のように「並列で比較する対象」であることが明確な場合にのみ使う。

- 料金プラン（Standard と 創業メンバーを比較する）
- FAQ（開閉する独立した項目）

次のものは**漫画またはストーリー表現を優先**する。

- 悩み
- メリット
- 導入効果
- ストーリー
- 顧客体験
- 集客導線

### カードに見えてしまう条件（避ける）

- 白背景 ＋ 角丸 ＋ 影 ＋ 均等幅 の反復
- 各カードに同じ構造（アイコン＋見出し＋説明）が並ぶ
- カード間に均等な gap があり、外側に余白がある

### カードに見せない実装

- 画像を**1枚につなげる**（内部に境界を作らない）
- 角丸・影・枠線を**外す**
- 帯を**全幅**にする（カードは必ず左右に余白を持つ。全幅の帯は「面」として読まれる）
- テキストブロックに `background` / `border` / `box-shadow` を**付けない**
- 帯の地色を画像の地色と**一致させる**（継ぎ目を消す）

---

## 4. HUMAN SCALE ／ 人物を小さくしない

**人物を小さな丸アイコンにしない。**
人物はセクションの主役になれる大きさで使い、**表情が読めること**を最低条件とする。

判断の目安：

- 人物の顔が概ね 40px 四方を下回るなら小さすぎる
- スマホ（375px）で人物が判別できない構図なら、シーン単位に再構成する
- 横長の集合イラストを 375px へ丸ごと縮小しない

---

## 5. SPEECH BUBBLES ／ 吹き出し

吹き出しは Salon デザインの重要要素。ただし**意味のない装飾として乱用しない**。

使う場面：

- 漫画内の感情
- 課題
- 変化
- 気づき

使わない場面：

- 機能名を並べるだけ
- HTML 本文と同じ内容を重ねる（**重複表示は禁止**）

画像内に吹き出しがある場合、HTML 側で同じ内容の吹き出しを重ねない。
HTML は「見出し＋短い補足」に留める。

---

## 6. DENSITY ／ 情報密度

**過剰な余白を避ける。**
高級ブランド LP のように、1メッセージだけで1画面を消費しない。

Salon が重視するのは
**「見ればサービス全体が理解できる」**情報密度である。

目安：

- 1440px で1セクションが概ね 700〜1,100px（1画面前後）に収まる
- 「巨大な H2 だけで画面が埋まる」構成にしない
- セクション余白は `clamp(44px, 7.5vw, 96px)` 程度。これを大きく超えない
- スマホの全長は 20〜23画面程度を目安とする（情報を削って短くするのではなく、
  重複説明・過剰余白・大きすぎるカードを削る）

---

## 7. ASYMMETRY ／ 非対称

均等グリッドだけで構成しない。広告 LP らしい非対称構成を積極的に使う。

- 人物大 ＋ UI 小
- 漫画左 ＋ 説明右
- UI 中央 ＋ 人物左右
- 背景の色面をまたぐ
- 吹き出しが境界を越える
- 列幅を内容の実寸比に合わせる（例 `487fr 474fr 546fr`）

同じ角丸ボックスが縦に連続する構成は、それ自体が失敗のサイン。

---

## 8. MOBILE ／ スマホ

**PC の横長画像をそのまま 375px へ縮小しない。**

スマホでは必要に応じて次の単位へ再構成する。

- コマ単位
- 人物単位
- シーン単位

優先順位は **画像内文字が読めること > 1枚に収めること**。

- CSS による横スクロールは原則使わない
- 画像は原寸を超えて拡大しない（拡大するとイラストの線と文字がぼやける）
- 素材の実寸が 560px なら、表示上限も 560〜640px 程度に留める
- 375px では画面幅いっぱい（全幅）まで使ってよい。カードにしない

### 実測の目安

| 素材の実寸 | 375px 表示 | 文字の実効サイズ |
|---|---|---|
| 560px 幅の1シーン | 375px（0.67倍） | 元28px の吹き出し文字 → 約19px。可読 |
| 1507px 幅の横長3シーン | 375px（0.25倍） | 約7px。**判読不能**。縦再構成が必須 |

---

## 9. ブレークポイント

既存の4段だけを使い、**増やさない**。

```
1080px 以下 : タブレット横 / 小型ノート（ナビをドロワーへ）
 860px 以下 : タブレット縦
 640px 以下 : スマートフォン
 520px 以下 : 小型スマートフォン
```

---

## 10. タイポグラフィ下限

- 本文 **16px**、注記 **14px** を下限とする。13px 以下は使わない
- `components.css` 由来で 12〜13px になる箇所は `.salon-theme` 配下で引き上げる
  （`components.css` 自体は変更しない）
- タップ領域は **44px 以上**
